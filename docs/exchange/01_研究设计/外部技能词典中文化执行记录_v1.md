## 3. 固定中文化规则

1. 通用能力和领域知识必须结合定义与类别翻译，不按英文名称机械直译。
2. 软件、产品、框架、编程语言和标准缩写默认保留英文原名。
3. 短通用软件表达，例如 `Robotic control software`，不按产品名自动处理，继续交由Codex翻译。
4. 中文规范名必须能够作为招聘文本匹配项，不使用解释性长句。
5. Codex生成的中文和中英混合别名全部先设置为 `is_active=0`。
6. 中文候选别名只有在招聘语料中实际出现，并通过歧义检查后才能激活。
7. 外部来源原始英文别名继续保留；新增缩写和补充英文别名仍需歧义检查。
8. `ambiguity_flag=1`的记录必须同步设置为 `translation_status=needs_review`。

## 5. 20项试译结论

试译覆盖领域知识、通用工作技能、其他职业技能和软件工具四类。自动Schema检查问题数为0。

试译确认以下规则是必要的：

1. `translate keywords into full texts`应译为根据关键词撰写完整文本，不能误译为语言翻译；
2. O*NET的 `Monitoring`应依据官方定义处理为对个人或组织绩效的监测与评估，裸词监控不宜直接激活；
3. `Practice management software PMS`在医疗语境下可译为诊所管理软件，但裸缩写PMS存在跨行业歧义；
4. `Microsoft PowerPoint`、`Apple Logic Pro`和 `McTrans HCS+`应保留产品英文名称；
5. `Robotic control software`是通用技术类别，应译为机器人控制软件，不能当作产品名只保留英文。

## 6. 当前产物的使用限制

`bilingual_partial_v0.2`只用于检查翻译流程和继续增量构建：

- 不用于正式岗位技能匹配；
- 不用于计算技能AI共现率；
- 不将新增中文候选别名设置为激活；
- 不视为正式词典版本冻结；
- 后续结果可以按 `skill_id`覆盖当前候选，但不得静默删除原始结果和运行日志。
